  format 44 is VK_FORMAT_B8G8R8A8_UNORM. 771 frames over a 15s hold is about
  51 fps against the 60Hz FIFO cap, the shortfall being the seconds before the
  run loop is reached. Picture: 2026-09-20-r0-vulkan-present.png.

  The clear is MAGENTA, not black, and that is the whole point of the arm. A
  Metal layer that was created and never presented is also black, so a black
  window proves nothing. Magenta is the same "nothing was drawn here" sentinel
  the software GS already uses. The first run of this arm did clear to black
  and was discarded as unfalsifiable.

VERDICT: PROGRESSED. Both halves of the R0 exit hold on one binary.


Loose ends, none of them blocking R1:

- The swapchain is built twice at startup. SDL emits a PIXEL_SIZE_CHANGED
  right after window creation and the present path honours it. One wasted
  swapchain, no visible effect.

- The drawable comes back 640x448, point resolution, despite
  SDL_WINDOW_HIGH_PIXEL_DENSITY. On a retina display a 2x drawable was
  expected. R1 compares frame signatures rather than screen pixels so it does
  not care, but a native renderer eventually will.

- The Vulkan path has no input and no debug panel. There is no raylib window,
  so IsWindowReady() is false and the pad stubs already gate on exactly that.
  Nothing to fix until the Vulkan path is the one being played.
